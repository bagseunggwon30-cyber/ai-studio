### 순서
1. 규칙은 `src/core/run_state.gd`의 RunState만 부른다. 씬 스크립트에 시간·체력·승패 계산을 새로 쓰지 않는다.
2. 메인 씬 스크립트가 RunState 하나를 만든다: `var state := RunState.new()` → `_ready()`에서 `state.setup(arena_rect, start_pos)`.
3. `_physics_process(delta)`에서 `state.tick(delta, 입력 방향)`을 부르고, 플레이어 노드 위치는 `state.player_pos`로 맞춘다. 노드가 스스로 움직이지 않는다 (`move_and_slide` 쓰지 않음).
4. 입력 방향은 `Input.get_vector(왼, 오, 위, 아래)` 하나로 받는다. 방향키만이면 기본 `ui_left`·`ui_right`·`ui_up`·`ui_down`, WASD를 더하려면 `project.godot`의 [input]에 동작을 추가한다 (작업 카드가 project.godot를 허용할 때만).
5. 코어·출구·적은 Area2D의 `area_entered`/`body_entered` 시그널에서 `state.collect(id)`·`state.reach_exit()`·`state.take_hit()`을 부르고, 돌려받은 true/false로만 화면을 바꾼다 (예: 주운 코어 숨기기).
6. 크기는 기본 해상도 640×360 기준. 방(arena)은 벽 두께만큼 안쪽 Rect2로 정하고, 플레이어·코어·출구를 그 안에 둔다.

### 흔한 실수
- 씬에서 `state.hp -= 1`처럼 상태를 직접 바꾸기 → RunState 메서드만 쓴다.
- 물리로 움직여 RunState 위치와 어긋나기 → 위치는 늘 `state.player_pos`를 따른다.
- 스페이스 들여쓰기·타입 없는 변수 → 탭 들여쓰기, 정적 타입.
- 함수 이름이 헷갈릴 때 짐작하기 → Godot 도움말(MCP `godot-docs`)로 먼저 확인한다.

### 확인
- 메인 씬 경로가 `project.godot`의 `run/main_scene`에 들어갔는지 본다.
- 가능하면 Godot를 headless로 한 번 열어 스크립트 오류가 없는지 본다.
