# 기능 서랍과 작업대

진행판 메뉴의 **기능 작업대**에서 연다. 왼쪽은 재사용 기능·작업 묶음 서랍, 가운데는 노드와 연결, 오른쪽은 선택한 노드 설명·입력·결과, 아래는 실행 장부다. 진행판·결재함·업무 일지는 기존 화면으로 열린다. 직원 그림은 담당 표시로만 쓴다.

## 첫 사용

1. **새 글 처리**를 누르고 입력 노트에 글을 쓴다. 기본 흐름은 입력 → 목록 정리 → 결과정리다. 파일을 변경하거나 모델을 호출하지 않는다.
2. 왼쪽에서 기능을 **꺼내기**로 추가한다. 출발·도착을 선택해 **연결하기**를 누른다. 노드는 드래그하거나 선택 후 방향키로 옮긴다. 오른쪽에서 입력을 수정하거나 작업대에서 제거한다. 서랍의 원본은 그대로 남는다.
3. 작업 묶음 이름과 보관 폴더를 정하고 **서랍에 저장**한다. 왼쪽 **작업 묶음**에서 다시 불러온다. 탭을 닫거나 페이지를 새로 고쳐도 이 브라우저의 작성 중 흐름을 복원한다.
4. **실행 계획 확인**에서 처리 순서·입력·작업 대상·허용 경로·담당/모델·호출 상한을 확인한다. 확인란을 체크하고 실행한다. 모델 작업에는 별도의 모델 사용 확인도 필요하다.
5. 장부의 실행을 선택하면 당시의 그래프·노트 버전·입력·출력·오류를 읽는다. 실행 기록은 읽기 전용이다. **사본으로 꺼내기**로 새 흐름을 만든다.

## 기능 노트와 실행 명세

**+ 노트**는 제목·폴더와 목적/입력 설명/출력 설명/주의/예시를 저장한다. 설명과 참고 코드는 문서다. 실행 명세는 미리 등록된 종류와 그 종류의 옵션으로 따로 정한다. 기본 노트는 사본으로 저장해 수정한다. 사용자 노트의 편집은 새 버전을 만들고 기존 묶음·장부는 이전 버전을 유지한다.

| 기능 | 실제 동작 |
| --- | --- |
| 입력 노트·문장 정리·목록 정리·입력 조건 확인 | 글 전달, 앞말/뒷말 붙이기, 중복 제거/정렬, 조건 검사. 모델 호출 없음 |
| 요구정리 | 기존 읽기 전용 기획 작업 한 번. 모델 호출 최대 1회 |
| 구현 | 기존 구현 → 신뢰 검증 → 읽기 전용 검토. 모델 호출 최대 2회 |
| 테스트·검토 | 구현 작업의 실제 검증/리뷰 기록과 후보 SHA 확인. 추가 명령/모델 호출 없음 |
| 사용자승인 | 기존 결재 창의 CEO 승인 대기. 구현은 검증 후보를 기존 승인 흐름으로 병합 |
| 결과정리 | 앞 노드의 실제 결과를 장부에 저장. 모델 호출 없음 |
| 자유 코드·셸 | 지원하지 않음. 이유를 표시하고 꺼내기를 비활성화 |

**구현 묶음**은 입력 → 구현 → 테스트 → 검토 → 사용자승인 → 결과정리다. 입력과 수용 기준을 적고 기존 프로젝트의 허용 범위 안에서 경로를 정한다. 구현의 검증 실패나 리뷰 수정 요청은 자동으로 재시도하지 않는다. 기존 작업 상세의 보고서·산출물·실행 정보와 결재를 그대로 사용한다.

**기획 묶음**은 입력 → 요구정리 → 사용자승인 → 결과정리다. 기획 결재로 생긴 자식 카드는 진행판에서 내용을 확인한 뒤 별도로 직접 실행한다. 작업대가 자식 작업이나 회고를 자동으로 연쇄 호출하지 않는다.

문서 내보내기/불러오기는 작업 묶음 JSON을 사용한다. 불러오는 노드 ID와 버전은 이 회사의 서랍에 있어야 한다. JSON이나 노트의 코드로 새 실행기를 설치하지 않는다.

## 연결·실패·복원

- 한 입력에는 한 연결만 허용한다. 입출력 형식 불일치·없는 노드·자기 연결·순환·중복을 거부한다. 작성 중 빈 흐름/미연결 노드는 저장할 수 있지만 실행 전 입력·연결·수용 기준을 검사한다.
- 모델 작업은 사용자승인 노드가 필요하다. 담당 직원이 없거나 현재 지원하지 않는 런타임이면 이유를 표시하거나 계획을 거부한다. 작업대에서는 Grok 텍스트 실행/대체 실행을 지원하지 않는다.
- 실행 계획은 그래프·노트 버전·프로젝트·검증·허용 범위·모델/MCP 설정과 함께 확정된다. 확인 이후 설정이 바뀌면 실행/호출을 막고 새 확인을 요구한다. 비밀 토큰은 계획에 넣거나 조회하지 않는다.
- 중복 클릭이나 실행 응답 유실 시 같은 확인 번호로 재전송해 같은 장부를 받는다. 새 작업을 중복 제출하지 않는다.
- 조건 오류는 노드를 막고 후속 노드를 건너뛴다. **기록 다시 확인**은 기존 결과를 다시 읽는다. 모델 재제출·자동 재시도는 하지 않는다.
- 프로그램 재시작은 진행 중 장부를 막힘으로 돌린다. 불확실한 제출은 다시 제출하지 않는다. 기존 작업이 준비 상태로 남았다면 그 작업의 실행을 사용자가 별도로 요청해야 한다.
- **후속 진행 중단**은 그래프의 새 제출만 중단한다. 이미 제출된 작업은 기존 작업창에서 별도로 중단한다.

흐름은 최대 24노드/48연결, 목록 정리는 200줄, 서랍은 종류별 500개, 폴더는 100개, 장부는 2000회로 제한한다.

## 저장과 운영

첫 저장/실행 때 회사 데이터 폴더에 `workbench.json`, `workbench-ledger.json`, `workbench-runs/W….json`을 원자적으로 저장한다. 기존 이벤트 기록에는 `workbench.*`를 추가하며 기존 작업의 일지·결재·산출물 저장 방식은 유지한다. 기존 데이터의 마이그레이션이나 수정은 필요 없다.

운영은 기존 `studio.server`와 `Engine`이 직접 담당한다. 이 개발 세션이나 별도 소윤/로컬 Codex 중개 세션은 필요 없다. 실제 모델 작업에는 기존 회사에 설정한 CLI 로그인과 직원 구성이 필요하다. 기획/구현을 사용자가 확인하고 실행하면 기존 구독 사용량을 쓴다.

이번 구현은 운영 서버를 다시 시작하거나 실제 작업을 제출하지 않았다. 이미 실행 중인 구버전 서버가 있다면 다음 안전한 서버 재시작 때 새 API가 로드된다. 화면에서 API 미지원 안내가 나오면 새 코드로 서버를 시작한 뒤 페이지를 새로 고친다.

개발 미리보기는 `python tools/dev/workbench_fixture.py --port 8798`이다. 별도 임시 회사·기존 `tests.helpers.FakeRuntime`·실제 QA/결재를 사용하며 127.0.0.1에만 연다. 콘솔에 `stop`을 입력하면 이 미리보기만 닫고 임시 회사를 정리한다. 실제 회사에 `--fake`를 사용하지 않는다.
