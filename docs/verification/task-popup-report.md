# 기획 질문 처리·작업창 넘침 수정

2026-10-04, S 드라이브 작업 폴더에 구현하고 실제 8765 서버에 반영했다. 기존 인증서 복구·기획 설명 저장·업무일지/완성작 개선 변경은 보존했다.

기획 실행은 AI Studio 화면 요청을 Core Courier 게임 프로젝트에서 처리할 수 있는지 질문한 상태였다. 질문을 실행 고장과 같은 `막힘/재시도`로 표현하고 답변할 경로가 없어 진행할 수 없었다. 재기획 이후에는 같은 초에 변경된 상태를 화면의 상세 캐시가 놓쳐, 서버에 후보가 있어도 화면에서는 0개로 보이는 문제도 확인했다.

## 변경한 동작

- 질문이 있고 작업 후보가 없는 유효한 기획은 `답변 필요`로 표시한다. 내부 상태 코드는 기존 `blocked`를 유지하고, API 요약/상세에 `needs_plan_input`을 추가했다. 실제 오류·잘못된 기획안은 기존 막힘과 재시도를 유지한다.
- `설명·질문 보기 → 답변하고 다시 기획`에서 CEO 답변을 기존 수정 요청 API로 보낸다. 이전 기획 체크포인트를 지우고 의견을 포함한 새 읽기 전용 기획을 요청한다. 입력 중인 답변은 화면 갱신으로 지워지지 않는다.
- 답변 없는 단순 재시도와 외부 감독 명의의 답변 재개를 차단한다. 불확실한 쓰기 기록은 지우거나 자동 반복하지 않는다. 최종 승인·병합·모델/프로젝트 권한을 확대하지 않았다.
- 작업창 높이를 제한하고 본문만 스크롤한다. 닫기와 행동 단추를 보이는 자리에 유지하며 버튼 글자·긴 문자열을 줄바꿈한다. 작업 제목을 세 줄로 정리하고 전체 요청은 본문에서 읽는다. 게시판의 600자 요약 대신 저장된 상세 내용을 조회한다.
- 명령창에 `대상: 프로젝트명`을 표시하고 순환 선택 대신 설명/허용 파일 범위가 있는 선택 목록을 제공한다. 목록에 없는 프로젝트가 아직 등록되지 않았음을 안내한다.
- 상세 캐시는 수정 시각 외에 작업 상태와 실행 횟수도 비교한다. 늦게 도착한 대기 응답이 최신 기획안을 덮어 보이지 않게 한다.

코드/화면: studio/model.py, studio/engine.py, studio/server.py, ui/popups.js/css, ui/data.js, ui/app.js, ui/board.js. 검사: tests/test_engine.py, tools/dev/task_popup_fixture.py, tools/dev/task_popup_smoke.js.

## 마지막 변경본 검증

- 관련 Python **23개: 23통과·0생략·0실패·0오류**, 45.551초. 서버 권한 검사, 질문/답변 후 새 기획, 답변 없는 재시도 차단, 불확실한 쓰기 보존, 정상 기획→검증→리뷰→사람 승인 흐름을 가짜 실행기로 확인했다.
- 진행판 12개 통과, UI JavaScript 문법 10파일과 브라우저 검사 파일 1개 통과.
- 실제 Edge에서 **44개 확인 항목 통과**. 1536×1024, 1024×768, 800×600, 600×900에서 창·닫기·본문·버튼 경계와 긴 문자열을 확인했다. 임시 회사의 실제 UI/API와 가짜 실행기로 답변 요청 1회→새 기획 1회→후보 2개→사람 결재 대기까지 검증했다. 지연된 조회 응답 1개를 시험용으로 만들어 캐시 복구도 확인했다. [브라우저 근거](task-popup-browser.json).
- 실제 회사는 자동 진행 꺼짐·진행/대기 실행 0개·활성 자동 업무 0개를 확인한 뒤 서버를 재시작했다. 기존 작업·회사/신뢰 설정 파일 해시와 실행 기록 수가 보존됐고 모델 추가 호출 0회다. 기존 취소 기획은 재개하지 않았다. 실제 회사 화면에서 기존 취소 카드의 창 경계를 읽기 전용으로 확인했다. [서버 적용](task-popup-live.json), [실제 화면 조회](task-popup-live-browser.json).
- 현재 HEAD에 미커밋 변경이 있는 상태이며, [소스 해시와 명령](task-popup-fix.json)으로 검증한 코드 상태를 구분한다. 이전 전체 검사나 부분 검사와 수를 합산하지 않는다. 최초 검사 명령의 존재하지 않는 `tests.test_model` 지정 오류는 수정했으며 위 23개가 올바른 마지막 검사 결과다.

전체 저장소 회귀 검사와 실제 Codex/Grok를 다시 호출한 재기획은 이번 수정에서 **실행 안 함**. 이번 브라우저 재기획 결과는 가짜 실행기 검증이며 실제 모델 성공으로 표시하지 않는다. main 병합이나 GitHub push는 하지 않았다.

## 사용 방법과 남은 범위

실제 AI Studio 화면을 새로고침하면 적용된다. 질문 대기 카드에서 설명·질문을 읽고 답변을 작성한다. 답변 버튼을 누르면 기존 프로젝트에서 기획이 다시 실행되므로 등록된 작업 대상을 먼저 확인한다.

AI Studio 프로그램 자체는 현재 직원의 제품 프로젝트로 등록돼 있지 않다. `studio-docs`는 보고서 저장소이며 프로그램 소스 작업을 대신하지 않는다. 해당 등록은 신뢰 프로젝트/수용 기준과 수정 권한을 정하는 별도 CEO 승인 사항으로 남겼다. 이번 수정에서 실제 회사의 등록·권한을 바꾸지 않았다.
