# 프로젝트 등록과 작업 대상 변경

2026-10-04. 현재 작업 브랜치에서 구현했고 main 병합·push는 하지 않았다.

## 사용하는 방법

1. 실제 AI Studio 화면을 Ctrl+F5로 새로고침한다.
2. 명령창의 `대상: …` → `프로젝트 등록`을 연다. `AI Studio 자체 입력`으로 이 저장소와 현재 브랜치, `ui/**`, `docs/design/**`, `tests/**` 범위를 채울 수 있다. 확인 체크 후 등록한다. 다른 기존 로컬 Git 저장소도 이름·ID·전체 경로·브랜치·수정 범위를 직접 입력해 등록한다.
3. 시작 전 또는 막힌 작업 카드의 `작업 대상 변경`을 누른다. 새 대상과 수정 경로를 확인하고 `대상 변경 · 실행 대기`를 선택한다.
4. 이전 카드는 취소 상태로 보존되고 새 카드가 막힘/확인 대기로 생성된다. 새 카드의 목표·수용 기준·수정 범위를 검토한 뒤 `재시도`로 시작한다. 실행에는 기존 구독 사용량이 들 수 있다.

직원 작업 사본은 선택한 브랜치의 커밋을 기준으로 만든다. 아직 커밋하지 않은 변경은 포함되지 않는다. 신규 등록에는 자동 QA가 없다고 표시하며 기존 검증 프로필은 변경하지 않는다. 리뷰와 CEO 결재 경계는 유지한다. 검증 명령은 이 화면에서 입력하거나 바꿀 수 없다.

## 보존과 제한

- 기존 보고서·실행 로그·체크포인트·작업 폴더를 유지한다. 새 카드에는 목표·수용 기준·요구사항과 새 수정 범위를 가져오며 이전 후보·QA·리뷰·실행 기록은 재사용하지 않는다.
- 진행/결재 중 작업, 후보 변경이나 검증 결과가 있는 작업, 불확실한 실행 기록, 변경된 작업 폴더, 자식/의존/공유 자원이 있는 작업은 이동을 거부한다. 외부 감독이 만든 작업의 프로젝트 권한도 이동하지 않는다.
- 원본을 먼저 일시 중지하고 새 카드를 생성한다. 생성 도중 중단되면 원본은 자동 실행되지 않는다. 생성 후 취소 경계에서 중단되면 같은 요청이 이미 생성된 카드를 반환하며 원본 재시도는 차단한다.
- 등록은 중복 ID/저장소와 잘못된 경로를 거부한다. 파일은 원자적으로 저장하며 감사 이벤트를 남긴다. AI Studio 자체 등록은 회사·신뢰·실행 데이터 영역을 보호한다.
- 등록과 이동 API는 기존 PC 세션 토큰·Host·Origin 검사를 통과해야 한다. 직원 MCP·외부 감독 MCP·휴대폰 API에는 관리 기능을 추가하지 않았다.

## 변경 파일

`studio/projects.py`, `studio/engine.py`, `studio/server.py`, `ui/data.js`, `ui/popups.js`, `ui/popups.css`, `tests/test_projects.py`. 임시 UI 검증 도구는 `tools/dev/project_management_fixture.py`, `tools/dev/project_management_smoke.js`다. 기존 병행 변경은 보존했다.

## 검증

최종 수치는 [검증 JSON](project-target-management.json)을 따른다. 표준 라이브러리 테스트는 실제 Git·임시 회사·가짜 실행기를 사용한다. 브라우저 검사도 임시 회사의 실제 Edge UI와 API를 사용한다. 실제 회사에서는 등록창·자동 입력·T0021 대상 변경 버튼을 읽기 전용 확인하고 재시작 전후 작업/회사/신뢰 설정 해시와 실행 기록 수를 비교했다.

실제 회사 프로젝트 등록·T0021 이동·Codex/Grok 호출 및 전체 저장소 회귀는 실행 안 함. 기존 회사 설정의 쓰기 범위는 사용자가 등록 화면에서 확인한 후에만 추가된다.
