# 소윤이 인증 실패의 안전한 단계 진단

사용자가 전달한 소윤이의 인증 검사 결과는 `blocked / ValueError`다. 해당 작업의 기록에서 Windows PC에서 지정된 `--read-only` 명령을 1회 실행한 사실을 확인했다. 원문 오류에는 실패 단계가 없어 정확한 원인을 판단할 수 없다. 소윤이의 인증 조회는 미완료이며 이전의 이 PC 성공 결과로 대체하지 않는다.

이 PC에서는 현재 등록 설정이 예상 설정과 같고 연결 전용 서버와 기존 취소 카드도 정상이다. 실행 환경의 Python·사용자 저장 위치 차이 등은 가능한 설명이며 아직 소윤이 쪽에서 확인하지 않았다. 다른 사용자 계정의 비밀정보를 읽거나 토큰을 교체하지 않는다.

## 수정과 검증

검사 CLI의 차단 결과에 `stage`를 추가했다. 설정 불일치는 승인된 항목 이름만 `different_fields`로 표시하고 추가 항목은 존재 여부만 표시한다. 설정 값·개인 경로·토큰·알 수 없는 항목 이름·원문 예외는 공개하지 않는다. 기존 설정 일치 검사와 승인 경계는 완화하지 않았다.

`--diagnose`는 설정 비교, GET health, 기존 카드 확인만 한다. MCP 프로세스·인증 파일 읽기·인증 도구·모델·제출·취소는 시작하지 않는다. `--owner-approved`를 함께 주어도 진단만 수행한다. 이 PC에서 실제 무인증 사전 진단은 통과했다. [집계 JSON](soyun-config-preflight.json). 소윤이의 진단 성공이나 인증 성공을 주장하지 않는다.

코드 `690d09444d887096c74a64714f3f10193f4eda4f`에서 연결 관련 10개 검사가 통과했다. 기존 8개에 설정 값/알 수 없는 키 이름 미노출, 진단에서 인증·MCP·쓰기 모드 진입 금지 검사를 추가했다. 이번 수정 뒤 PC 전체 검사는 실행하지 않았다. 이전 279개 PC 전체 결과는 이전 코드의 결과다.

이 코드의 Windows GitHub Actions 전체 검사는 **281개 중 261통과·20생략·0실패/오류**다. 생략은 Godot 부재 19개와 POSIX 프로세스 그룹 1개이며 통과로 세지 않는다. 진행판 12개와 JavaScript 문법 10파일, 가짜 모델 stdio 왕복도 통과했다. 209초 동안 검사했고 소스 불변을 확인했다. [회귀 JSON](soyun-diagnosis-ci/regression.json), [가짜 모델 왕복 JSON](soyun-diagnosis-ci/supervisor-fake.json), [실제 실행](https://github.com/bagseunggwon30-cyber/ai-studio/actions/runs/37124312853). 로그인·모델 호출·비밀정보 없는 CI이며 실제 소윤이 연결 검증을 대신하지 않는다. 이후 커밋은 문서·근거만 추가한다.

소윤이에게 보낼 준비된 요청문은 [연결 안내](../SOYUN_CONNECT.md)에 있다. 소윤이에 직접 메시지를 보내거나 직원 모델을 추가 실행하지 않았다. 직접 진단 메시지 1회 전송은 사용자 선택을 요청했으며 아직 승인·전송하지 않았다. 실제 회사의 설정·권한·제품 파일·카드 상태는 수정하지 않았고 main 병합·배포·공개 서버·새 인증 정보도 만들지 않았다.
