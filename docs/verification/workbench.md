# 기능 서랍·재사용 노드 작업대·실행 장부 — 완료 보고

2026-10-04. 기능 브랜치 `codex/node-workbench-20261004`, 구현 커밋 `2b6079f`. 사용법은 [기능 작업대 안내](../WORKBENCH.md).

## 구현 결과

- 왼쪽 기능/작업 묶음 서랍, 가운데 연결 그래프, 오른쪽 노트·실행 입력/결과, 아래 실행 장부를 웜화이트/청록으로 구현했다. 진행판은 전체 업무 조회용으로 유지하고 기존 직원 그림은 담당 표시로 쓴다. 사무실 복원·펫 제작은 하지 않았다.
- 폴더 생성/이름 변경, 노트 생성/편집/버전 저장, 작업 묶음 생성/이름·폴더 편집/저장·불러오기, JSON 내보내기/불러오기, 브라우저 초안 복원을 제공한다. 서랍 원본과 실행 사본을 구분하며 예전 흐름·장부의 노트 버전은 바뀌지 않는다.
- 노드 추가/제거/드래그/방향키 이동/연결·해제, 입력 검사, 순환·중복·없는 노드·형식 불일치 거부를 구현했다. 실행 당시 그래프·명세·버전·노드 입력/출력/오류·기존 작업 기록을 보존한다.
- 등록된 글 처리와 모델 판단을 구분한다. 노트의 참고 코드·셸·HTML은 실행하지 않는다. 기본 요구정리/구현/테스트/검토/사용자승인/결과정리는 현재 엔진이 실제 지원하는 방식으로 연결했다. 자유 코드·셸은 이유와 함께 비활성화한다. 작업대의 Grok 텍스트 실행은 지원하지 않는다.
- 실행 전 순서·파일 허용 범위·담당/실효 모델·MCP 이름·호출 상한을 확인한다. 모델 사용은 별도 확인한다. 확인 이후 프로젝트·검증·범위·모델/MCP 설정 변경을 막는다. 계획 조회는 MCP 비밀값을 읽지 않는다.
- 기존 Engine의 작업 제출·샌드박스·신뢰 검증·읽기 전용 리뷰·CEO 결재·일지·산출물을 재사용한다. 실제 작업 이벤트로 상태와 연결선을 갱신한다. 별도 실행기나 개발/소윤/로컬 Codex 중개 세션은 필요 없다.
- 같은 실행 확인 번호의 재전송은 같은 장부를 반환한다. 모델 작업은 자동 재시도·대체 재호출·회고 자동 생성이 없다. 기획 자식 카드는 별도 수동 실행이다. 재시작 뒤 진행 장부는 막힘으로 돌리고 불확실한 제출은 재제출하지 않는다.

전체 회귀는 `python tools/dev/workbench_regression.py`로 **`python -m unittest discover -s tests -t .`와 동일한 전체 suite**를 실행했다. 진행 로그와 60초 진단 스택 출력만 추가하며 테스트·실행기·수용 기준은 바꾸지 않는다. 최종 실행은 정상 Windows 권한에서 기존 가짜 실행기·임시 회사만 사용했다. 생략 1개는 Windows에 해당하지 않는 POSIX process-group 검사다.

초기 표준 전체 검사(343개)는 샌드박스에서 기존 Godot 그림 처리의 사용자 로그 쓰기/인증서 읽기 거부와 시간 제한 문제로 실패 15·오류 2·생략 1이었다. 추가 진단 실행의 [실패 근거](workbench-regression-sandbox.json)도 보존했다. 정상 권한의 최종 전체 회귀에서는 모두 해결됐다. 이 문제 때문에 그림 제품 기능을 바꾸거나 작업 범위를 늘리지 않았다.

화면 검사는 임시 회사의 기존 FakeRuntime으로 구현·리뷰 두 번, 실제 신뢰 검증, 기존 결재 UI 승인·정확한 후보 병합·후속 장부 완료까지 확인했다. 응답 유실 후 재전송, 중복 클릭, 조건 실패·복구, 버전 고정, 저장/닫기/재열기/새로고침, 1536/1024/800/390 너비, HTML 입력도 점검했다. 의도적으로 만든 실패 응답·끊긴 응답의 네트워크 오류는 검사 대상이며 페이지 스크립트 오류와 구분한다.
