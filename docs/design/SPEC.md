# AI 스튜디오 게임 화면 설계서 (구현용)

> **(2026-10-06 메모) 도트 사무실(본사) 화면은 없어졌다.** `ui/scene.js`·`scene_sim.js`·층 배경·벽 쪽지·소환 연출·층 버튼은 지웠고, 직원 얼굴 정지 그림만 `ui/stills.js`가 맡는다. 아래 사무실·소환·층·벽 쪽지·소품 선반 관련 기록은 **옛 기록**이다. 지금 화면의 기준은 [modern-ui.md](modern-ui.md).

> 읽는 사람: 이 화면을 구현할 Codex.
> 기준 이미지는 이 폴더의 `01`~`10` webp, 스타일 규칙은 [README.md](README.md), 에셋 프롬프트는 [asset-prompts.md](asset-prompts.md).
> 이미지는 목업이다. 픽셀 단위로 똑같이 만들 필요는 없고, 배치·분위기·상호작용을 따른다.

## 1. 원칙

- 표와 목록 대신 캐릭터, 말풍선, 물건으로 상태를 보여 준다.
- 기본 화면은 본사 하나. 나머지는 사무실을 어둡게 깐 팝업이거나 회의실 장면이다.
- 상단 바와 하단 명령창은 어느 화면에서나 보인다 (목업에서 빠진 결재 창·완성작도 포함).
- 글자는 짧게. 긴 내용은 눌렀을 때만 보인다.
- 실제 데이터와 연결된 것만 그린다. 모르는 값을 숫자로 꾸며내지 않는다 (예: 진행률 %).

## 2. 기술 방향

- 로컬 웹 앱. 기준 캔버스 1536×1024를 창에 맞게 비율을 유지해 확대한다 (`image-rendering: pixelated`, 남는 곳은 어두운 여백).
- 레이어: ① 배경 그림 ② 캐릭터·소품 스프라이트 (절대 위치) ③ 팝업 ④ 상단 바·명령창·알림.
- 글자는 그림에 굽지 않고 HTML로 넣는다. 한글 픽셀 폰트 Galmuri11 (SIL OFL) 파일을 저장소에 포함한다. 다운로드는 CEO 승인 후.
- 외부 CDN과 무거운 게임 엔진 없이 바닐라 HTML/CSS/JS. 애니메이션은 CSS 스프라이트 프레임과 transform. 다른 도구가 필요하면 먼저 제안한다.
- 데이터는 기존 감독 프로그램 API(`studio/server.py`)에서 받는다 (7장).
- 새 화면은 `ui/`에 만든다. 기존 대시보드 파일은 `ui-old/`로 옮겨 보관한다.

## 3. 화면 지도

```
본사 (허브)
 ├─ 편지함 아이콘 → 결재함 → 기획안이면 회의실 / 개발이면 결재 창 / 리서치면 보고서
 ├─ 종 아이콘 → 알림 목록 (최근 활동)
 ├─ 빨간 버튼 → 긴급 정지 ↔ 재개
 ├─ 벽의 퀘스트 보드, 두루마리 버튼 → 퀘스트 보드
 ├─ 캐릭터 클릭, 사람 버튼 → 직원 상태창
 ├─ 책 버튼 → 업무 일지
 ├─ 회의실 클릭 → 회의실 (기획안이 없으면 "지금은 회의가 없어요")
 ├─ 완성작 선반 클릭 → 완성작 진열장
 └─ 명령창 → 지시 → 하나가 회의실로 이동 → 기획안이 준비되면 알림
```

## 4. 공통 요소

### 4.1 상단 바

| 요소 | 표시 | 데이터 | 누르면 |
|---|---|---|---|
| 로고, "AI 스튜디오" | 회사 이름 | 설정의 회사 이름 | — |
| "N일차 · 오전 10:20" | 회사 날짜와 현재 시각 | 첫 기록일부터 센 날짜, 로컬 시각 | — |
| 번개, 막대, "에너지 a/b" | 오늘 남은 실행 여유 | b = 하루 실행 상한, a = b − 오늘 실행 수 | 오늘 실행 횟수·시간 풍선 도움말 |
| 편지함, 빨간 숫자 | 결재 대기 수 | 결재 대기 상태 작업 수 | 결재함 |
| 종 | 새 알림 수 | 마지막으로 본 뒤 생긴 활동 수 | 알림 목록 |
| 빨간 둥근 버튼 | 긴급 정지 | 회사 정지 여부 | 확인 후 정지. 정지 중이면 눌린 모양 |

### 4.2 하단

- 버튼 3개: 두루마리(퀘스트 보드), 사람(직원 목록 → 상태창), 책(업무 일지).
- 명령창: "무엇을 시킬까요?". Enter나 보내기 버튼으로 지시를 만든다. 보내면 하나가 "알겠어요! 회의실에서 나눠 볼게요" 말풍선을 띄우고 회의실로 간다.
- 긴급 정지 중에는 명령창을 잠그고 "정지 중이에요"를 보여 준다.

### 4.3 알림 말풍선 (오른쪽 위)

- 직원 얼굴과 한 줄. 결재 요청 "솔: 결재 부탁드려요!", 보고서 "루나: 보고서 올렸어요!", 막힘 "솔: 막혔어요, 도와주세요".
- 5초 뒤 접힌다. 누르면 해당 화면이 열린다.

## 5. 직원

### 5.1 설정

| 이름 | 역할 키 | 책상 | 모니터 화면 |
|---|---|---|---|
| 하나 | producer | 윗줄 왼쪽 | 문서 |
| 솔 | builder | 윗줄 오른쪽 | 코드 |
| 클로 | reviewer | 아랫줄 왼쪽 | 문서 |
| 루나 | analyst | 아랫줄 오른쪽 | 표 |

이름, 한마디, 보유 스킬은 설정 파일에서 바꿀 수 있게 한다 (7장의 백엔드 추가 2번).

### 5.2 상태와 모습

| 상태 | 조건 | 모습 | 말풍선 |
|---|---|---|---|
| 작업 중 | 이 직원 역할의 에이전트가 실행 중 | 책상에서 타이핑 (2프레임 반복), 모니터 켜짐 | 단계 문구와 계속 흐르는 막대 |
| 휴식 | 맡은 일이 없음 | 휴식터로 걸어가 소파나 쿠션에서 쉰다 (커피, 고양이 곁) | 없음 |
| 결재 올림 | 이 직원의 작업이 결재 대기가 된 순간 | 손 흔들기 1회 | "결재 부탁드려요!" |
| 합격 | 품질 검사 통과 | 만세 1회, 반짝이는 합격 도장 | "합격!" |
| 막힘 | 이 직원의 작업이 막힘 | 머리 긁기, 산호색 "!" | "막혔어요" |
| 정지 | 회사 긴급 정지 | 그 자리에서 멈춤, 빨간 "!" | 없음 |

- 진행률(%)은 백엔드에 없다. 숫자 없이 계속 흐르는 막대로 보여 준다.
- 단계 문구: 기획 "기획안 쓰는 중…", 개발 첫 시도 "코딩 중", 수정 시도 "고치는 중", 검사 대기 "검사 받는 중", 리뷰 "검토 중…", 리서치 "자료 찾는 중…".
- 일이 생기면 휴식터에서 책상으로 걸어온 뒤 작업 중으로 바뀐다.

### 5.3 직원 상태창 (04)

| 항목 | 계산 |
|---|---|
| 레벨 | 1 + 완료 작업 수 ÷ 5 (내림) |
| 경험치 막대 | 다음 레벨까지: 완료 작업 수를 5로 나눈 나머지 / 5 |
| 속도 | 최근 10회 평균 실행 시간이 짧을수록 길다 (작업 제한 시간 대비) |
| 정확도 | 첫 시도 통과율 |
| 꼼꼼함 | 리뷰에서 막는 지적을 받지 않은 비율 |
| 보유 스킬 | 설정의 스킬 목록 |
| 오늘 완료 N · 수정 M | 오늘 결재된 수, 오늘 수정 시도 수 |
| 기분 | 최근 3회 결과. 성공이 많으면 웃음, 실패가 많으면 걱정 |
| 사진 옆 메모 | 설정의 한마디 |

## 6. 화면별

### 6.1 본사 (01)

- 클릭 영역: 퀘스트 보드, 회의실, 완성작 선반, 스킬 학습 게시판(기능 미정. 누르면 "준비 중"), 캐릭터 4명.
- 벽의 퀘스트 보드: 대기·진행 중·결재 대기 작업 수만큼 색 쪽지 (최대 4장).
- 완성작 선반: 완성작 수만큼 트로피와 카트리지, 나머지는 점선 칸.

### 6.2 퀘스트 보드 (02)

- 4열: 대기(준비, 기획 대기), 진행 중(작업 중, 검증 중), 결재 대기, 완료(최근 5개).
- 막힌 작업은 진행 중 열에 두고 산호색 "막힘" 띠와 걱정하는 담당 얼굴로 표시한다.
- 쪽지: 제목, 담당 얼굴, 난이도 별 1~3 (기획 담당이 매김. 없으면 1), 완료는 금 도장.
- 위쪽 종이 "이번 주 목표: …"는 CEO가 정한 문구 (설정 또는 화면에서 수정).
- 쪽지를 누르면 작은 카드로 목표, 수용 기준, 담당, 상태를 보여 주고, 할 수 있는 행동(실행, 재시도, 취소)을 단다.

### 6.3 회의실 (05)

- 기획안이 결재 대기일 때 열린다 (결재함이나 알림에서).
- 화이트보드: "지시: {지시 첫 줄}"과 카드 수만큼의 상자 그림.
- 카드: 기획안의 작업마다 1장 (최대 8장, 4장이 넘으면 두 줄). 제목, 담당 얼굴, 별, 체크 표시 (기본 체크).
- 카드를 누르면 목표와 수용 기준을 보고 제목을 고칠 수 있다.
- 하나의 말풍선: "{n}단계로 나눴어요. 골라 주세요!". 기획 담당의 질문이 있으면 "여쭤볼 게 있어요" 쪽지가 테이블에 놓인다.
- "퀘스트로 붙이기": 체크한 카드만 승인한다. 카드가 퀘스트 보드로 날아가는 효과.
- "다시 기획": 메모를 받아 재기획을 요청한다.

### 6.4 결재함 (08)

- 결재 대기 작업 전부. 편지 한 줄에 밀랍(기획 = 금색, 개발 = 빨강, 리서치 = 보라), 보낸 직원, 제목, 꼬리표.
- 꼬리표: 개발 "품질 합격" 또는 "검사 없음", 리서치 "보고서", 기획 "기획 회의".
- "열기": 종류에 따라 결재 창, 보고서, 회의실.

### 6.5 결재 창 (03)

- 제목 "결재 · {작업 제목}".
- 줄 1: "품질 검사 {통과}/{전체} 합격". 자동 검사가 없는 작업이면 "자동 검사 없음 · 직접 확인".
- 줄 2: "리뷰: 클로 승인". 클로 대신 Codex가 검토했으면 "리뷰: 대리 검토 (교차 검증 아님)".
- 줄 3: "바뀐 파일 {n}개". 누르면 종이를 뒤집어 변경 내용(diff)을 보여 준다.
- "승인" 도장: 누르면 도장이 쾅 찍히고 병합, 완료로 바뀐다. 담당 직원이 만세.
- "수정 요청": 메모를 받아 담당에게 보낸다.

### 6.6 보고서 (06)

- 리서치 작업이 만든 보고서 파일에서 읽는다: 제목, 한 줄 결론(결론 요약의 첫 문장), 핵심 주장 앞 3개, 출처 수, 확인 필요 수("미확인·한계" 항목 수).
- 출처 칩을 누르면 링크 목록, 확인 필요 칩을 누르면 해당 항목 목록.
- "전체 보기"로 보고서 전문을 읽기 모드로 연다.
- "확인 완료" = 승인(병합). "질문하기" = 질문 메모를 수정 요청으로 루나에게. 보관 아이콘 = 결재함에서 숨기고 '나중에 보기'로.

### 6.7 업무 일지 (07)

- 오른쪽 탭: 날짜별 ("1일차"부터). 최근 7일만 탭으로, 나머지는 넘김 화살표로.
- 왼쪽: 그날 주요 사건 시간순 최대 8줄 (작업 완료, 보고서 제출, 결재, 기획 회의, 막힘). 한 줄 = 시각, 얼굴, "{이름} · {짧은 내용}".
- 오른쪽 "오늘의 요약": 완료 수, 결재 수(CEO가 승인한 수), 에너지 사용(그날 실행 수), 첫 시도 합격 a/b, "내일: {다음 준비 작업 제목}".
- 스티커와 낙서는 장식이다.

### 6.8 긴급 정지 (09)

- 빨간 버튼 → 확인 팝업 → 정지.
- 붉은 조명 오버레이, 경광등 회전, 직원 모두 빨간 "!"로 멈춤, 모니터에 일시정지 표시.
- 가운데 배너 "긴급 정지 · 모든 작업 멈춤"과 "재개" 버튼.
- 정지 중에도 팝업은 열어 볼 수 있지만, 실행·승인 같은 행동 버튼은 잠긴다.

### 6.9 완성작 진열장 (10)

- 칸마다 완성작 하나. 게임은 카트리지(썸네일은 빌드 스크린샷, 없으면 기본 그림)와 "플레이"(빌드 실행 파일 열기). 보고서는 액자와 "열기"(보고서 화면).
- 명판: "완성 {n} · 이번 달 목표 {m}" (m은 설정).

## 7. 백엔드 연결

지금 있는 감독 프로그램 API를 쓴다.

| 필요한 것 | API |
|---|---|
| 전체 상태 (작업, 직원, 회사 상태, 활동, 실행 기록) | `GET /api/state` |
| 작업 상세, 변경 내용 | `GET /api/tasks/{id}`, `GET /api/tasks/{id}/diff` |
| 지시 | `POST /api/directive` |
| 실행, 승인, 수정 요청, 재시도, 취소 | `POST /api/tasks/{id}/run·approve·request-changes·retry·cancel` |
| 긴급 정지, 재개 | `POST /api/control/stop`, `POST /api/control/resume` |

백엔드에 새로 필요한 것:

1. 기획안 작업의 난이도(1~3). 기획 출력 형식에 추가한다.
2. 직원 설정: 이름, 한마디, 보유 스킬 (`studio.toml`의 역할마다).
3. 보고서 요약: 보고서 파일에서 제목, 결론, 주장, 출처 수, 확인 필요 수를 뽑아 돌려준다.
4. 업무 일지: 날짜별 사건 묶음과 요약.
5. 직원 통계: 완료 수, 첫 시도 통과율, 평균 실행 시간, 막는 지적 비율, 오늘 완료·수정 수.
6. 완성작 목록: 완료된 보고서는 자동 등록, 게임 등록 방식은 결정 필요 (9장).
7. 결재함 '보관' 표시와 알림 읽음 표시.
8. 설정: 이번 주 목표, 이번 달 완성 목표.

- `ui/data.js`가 `/api/state`를 1.5초마다 읽는다 (끊기면 5초마다). 버전(`실행마다 다른 접두어.변경 번호`)이 같으면 다시 그리지 않는다. 작업 상세·보고서 요약·변경 내용·일지는 처음 볼 때만 불러온다.
- 7장의 새 백엔드 항목 (`studio/company.py`, `studio/server.py`):
  1. 난이도: 기획 출력에 `difficulty`(1~3)를 받고 작업 카드에 저장한다.
  2. 직원 설정: `studio.toml` 역할마다 `name`, `character`, `memo`, `skills`. 목표는 `[goals]`(week, month), 이번 주 목표는 화면에서 고치면 `data/state.json`에 저장.

  4. 업무 일지: `GET /api/diary?day=N` — 그날의 완료·결재·기획 회의·보고서 제출·막힘·리뷰 수와 요약(완료, CEO 결재, 실행 수, 첫 시도 합격, 내일 할 일). 회사 1일차는 `state.json`의 `founded`.
  5. 직원 통계: 완료 수(레벨 = 1 + 완료 ÷ 5), 속도(최근 10회 평균 시간 ÷ 제한 시간), 정확도(첫 시도 통과율), 꼼꼼함(리뷰 한 번에 통과한 비율), 오늘 완료·수정, 기분(최근 3회). 기록이 없으면 빈 막대.
  6. 완성작: 리서치는 승인(병합) 때 자동 등록. 게임은 완료된 개발 작업 카드의 "완성작에 올리기"로 CEO가 올린다(9장 결정의 기본안). "플레이"는 Godot 프로젝트면 Godot로 main을 연다 (셸 없이 정해진 인자만, 선반에 있는 작업만).
  7. 결재함 보관(`POST /api/tasks/{id}/archive`)과 알림 읽음(`POST /api/alerts/read`).
  8. 설정: `POST /api/settings/goals`.
- 직원 모습은 서버가 정한다: 실행 중인 역할 = 작업(단계 문구: 코딩 중·고치는 중·검사 받는 중·검토 중… 등), 막힌 작업이 있으면 막힘, 아니면 휴식. 새 알림이 오면 잠깐 손 흔들기(결재 올림)나 만세(합격·완료)를 한 뒤 원래 모습으로 돌아간다.
- 알림(종)은 활동 기록 중 CEO가 알아야 할 것만 직원 말투로 바꿔 보여 준다. 누르면 해당 화면이 열린다.
