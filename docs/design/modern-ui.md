CEO가 보낸 세 장의 참고 화면(작업 흐름 화면 Nexora · 회색 칸반 Callbacks · 홈 화면 Pactwatch 영상)을 바탕으로 AI 스튜디오의 화면과 기능을 새로 정리했다.

## 화면 구성

- **홈(오늘)** `ui/home.js`: 인사 + 한 줄 요약("사장님이 정할 일이 결재 2건 · 막힌 일 1건 있어요. 나머지는 순조로워요.") → 핵심 숫자 3개(이번 주 끝낸 일 · 검사 통과율 · 오늘 실행) → **결정이 필요해요**(막힘 먼저, 줄마다 바로 처리 단추) · **전체 진행**(끝남/일하는 중/기다림/막힘 막대 + 직원별) → **다가오는 자동 업무**(없으면 최근 끝난 일).
- **진행판** `ui/board.js`: 위치 → 큰 제목 + 도구(프로젝트 · 프로젝트별로 묶기 · 칸반/목록 · 표 파일 내려받기 · 새 지시) → **보기 칩**(전체 · 결재 기다림 · 막힘 · 3일 넘은 일, 개수) + 이번 주 목표 + 직원 얼굴 → 지시별 진행(안 끝난 지시만) → 칸반(5칸, 카드가 없는 칸은 좁게) 또는 목록.
- **이미지·영상 작업대** `ui/media.js` + `ui/media.css` (왼쪽 메뉴 '작업' 묶음, 옛 '기능 작업대' 자리): 아래 절.
- **소설 집필실 · 디자인 작업실** `ui/rooms.js` + `ui/rooms.css` (왼쪽 메뉴 '작업' 묶음, 이미지·영상 작업대 아래): 작품(프로젝트)의 파일을 읽고 시작 버튼으로 일을 맡기는 화면. 아래 '작업 모드 화면' 절.
- **빠른 찾기** `ui/finder.js` (Ctrl K): 일·직원·스킬·화면. 비어 있으면 '지금 챙길 일'과 화면 바로가기.
- **주간 요약** 창 (`Home.digest`, 왼쪽 메뉴 아래): 최근 7일.
- **외부 연결 창** `ui/gateway.js` + `ui/gateway.css` (왼쪽 메뉴 '회사' 묶음, MCP 보관소·자동 업무 아래): ChatGPT·Dots 같은 바깥 AI 앱이 쓰는 'MCP 연결 문'을 켜고 끄고 권한·연결 번호·연결된 앱·기록을 보는 창. 아래 '외부 연결 창' 절. 안내는 `docs/MCP_GATEWAY.md`.

## 이미지·영상 작업대 (`ui/media.js` · `ui/media.css`, 2026-10-06)

CEO 요청 "기능 작업대를 이미지 및 영상 제작 작업대로" (참고: Nexora형 작업 흐름 화면). 홈·진행판과 같은 껍데기 안의 **페이지** `.bd-page-media`(동작 이름 `media`, 주소 `#view=media`)다. 글로 지시하면 서버가 이 PC의 공식 Grok 프로그램으로 그림·영상을 만들고(연습용 모의 서버에서는 가짜 파일), 이 화면은 그 일을 시키고 결과를 모아 보여 준다. 백엔드는 이미 있는 것만 쓴다: 읽기 `GET /api/workbench/media`, 만들기 `plan → (진짜면 Grok 계획·동의) → start`, 중단 `runs/<run>/halt`, 연결 `grok-everywhere connection-plan·configure·disconnect`.

**3단 구조** (무대 px, `.bd-main` 1256×804 안): 위쪽 줄(제목 + 한 줄 설명 + Grok 연결 칩 + '노드 편집기 (고급)') 아래 `.md-grid` = 왼쪽 250 · 가운데 나머지 · 오른쪽 330, 칸 사이 16.

| 칸 | 내용 |
|---|---|
| 왼쪽 `.md-left` | '새로 만들기' 큰 단추 2개(그림·영상, `.md-new`) → '내 작업물' 필터 칩(전체·그림·영상 + 개수, `.md-fchip`) + 카드 목록(`.md-card`: 썸네일 56, 지시 글 2줄, 종류 칩 `.md-kind`, 상태 칩 `.md-state` 점+글자, 몇 분 전). 키보드 ↑↓·Home·End·Enter, 탭은 한 칸만 잡는다(roving tabindex) |

**클래스 접두는 `md-`**. 색·간격·반경은 `--bd-*` 토큰만 쓰고 어두운 면은 없다. 흰 카드 + 연한 회색 칸 + 알약 칩 + 검은 주 단추 + 남보라 강조(위쪽 "한눈에" 규칙 그대로). 주의: `style.css`에 전역 `.warn`(산호색 말풍선 느낌표)이 있어 주의 색 클래스는 `caution`으로 쓴다 — 새 화면의 클래스 이름이 `warn`·`bad`·`on` 같은 흔한 낱말 하나뿐이면 옛 규칙과 겹칠 수 있으니 `md-` 짝 클래스로만 쓴다.

**안전 규칙** (화면이 지킨다):
1. 한 번 누르면 한 번만 보낸다 — [만들기]는 누르는 순간 잠그고(`reviewing`), 확인 창의 [한 번 보내기]도 누르는 순간 잠근다(`sending`), 같은 `request_id`.
2. 보내기 전에 **정확한 지시 글·종류·길이**(서버 `plan`이 알려 준 값 그대로)를 확인 창에 다시 보여 주고, 진짜면 "이 요청을 Grok에 한 번 보냅니다 · 비용 알 수 없음" 체크를 받아야 [한 번 보내기]가 켜진다. 연습용(`simulation`)이면 체크 없이 "연습용 · 실제 생성 아님"을 크게 보인다.
3. 실패·결과 불확실이면 **자동으로 다시 보내지 않고**, 같은 창에서는 다시 못 누르게 잠그며, 다시 만들려면 처음부터(새 계획·새 체크) 한다. '같은 지시로 다시 만들기'와 예시 칩은 글상자만 채운다.
4. 진짜 승인 순서는 기존 작업대와 같다: `GET /planner`(설정 해시) → Grok `plan` → `consent` → `start`(승인 번호 `provider_grants`).

**움직이는 부분 보존**: 이 화면이 보이고 만드는 중인 작업이 있을 때만 3초마다 `GET /api/workbench/media`를 읽는다(화면을 떠나거나 탭이 숨으면 멈춘다). 읽은 뒤에는 바뀐 부분만 고친다 — 목록 카드는 자리를 지키며 고치고, 가운데 무대는 상태·결과가 바뀔 때만 다시 그리며, 오른쪽 글상자는 한 번만 만들어 두고 끼웠다 뺀다. 그래서 입력 중인 글·초점·스크롤·재생 중인 영상이 끊기지 않는다.

**캡처** (`docs/design/captures/`): `modern-media-empty`(처음 쓰는 모습: 연결됨 · 아직 없음) · `-image`(그림 결과) · `-video`(영상 결과, 컨트롤 보임) · `-working`(만드는 중 + 막힘·중단이 섞인 목록) · `-confirm`(정확한 요청 확인 창) · `-connect`(연결 안 됨 + 연결 창). 눌러 봐야 하는 상태라 `node tools/dev/media_browser.cjs --shots`가 연습용 모의 서버에서 남긴다 (`media` 이름만 `capture.ps1`에도 있다: 첫 화면). 일부 캡처(만드는 중·막힘·영상 실제 길이·확인 창)는 서버 응답을 `page.route`로 가공한 견본이다 — 진짜 Grok은 부르지 않는다.

## 작업 모드 화면 — 소설 집필실 · 디자인 작업실 (`ui/rooms.js` · `ui/rooms.css`, 2026-10-06)

CEO 요청 "개발 모드 외 디자인 및 소설 작성 부분도 추가해줘". **모드 = 프로젝트 종류(kind)** 다: 개발(`generic`·`godot`·`docs`) · 디자인(`design`) · 소설(`novel`). 같은 직원(하나 기획 · 솔 개발/집필 · 클로 리뷰 · 루나 리서치)과 같은 흐름(기획 → 작업 폴더에서 만들기 → 리뷰 → 사장님 결재 → 병합)을 쓰고, 직원에게 가는 지침만 종류에 따라 다르다 (서버 `studio/modes.py`). 이 화면은 **그 일을 시키고 결과 파일을 읽는 곳**이다. 새 서버 일은 없다: 모드·시작 버튼 `GET /api/modes`, 새 프로젝트 `POST /api/projects/new`, 파일 `GET /api/projects/<ID>/tree·file·raw`, 일 맡기기 `POST /api/modes/start`.

홈·진행판·이미지·영상 작업대와 같은 껍데기 안의 **페이지**다: `.bd-page-novel`(동작 이름 `novel`, 주소 `#view=novel`)과 `.bd-page-design`(`design`, `#view=design`), 왼쪽 메뉴 '작업' 묶음에서 이미지·영상 작업대 아래. **같은 컴포넌트 `Rooms.create(mode)`가 모드만 달리해 두 페이지를 그린다** (글·폴더 묶음·이름표는 `Rooms.logic.MODES·FOLDERS·LABELS`).

**3단 구조** (무대 px, `.bd-main` 1256×804 안): 위쪽 줄(위치 · 큰 제목 + 한 줄 설명 · [새 작품 만들기] / [새 디자인 프로젝트 만들기] · 프로젝트 고르기 칩 줄) 아래 `.rm-grid` = 왼쪽 270 · 가운데 나머지 · 오른쪽 330, 칸 사이 16.

| 칸 | 내용 |

**안전 규칙** (화면이 지킨다):

## 창(팝업)을 새 모양으로 바꿀 때 규칙

1. 창은 **흰 판**(`#stage.view-board .paper`가 이미 흰색·모서리 28·부드러운 그림자). 나무·코르크·종이·테이프·핀·밀랍·두꺼운 테두리·딱딱한 그림자(`0 8px 0`)는 모두 없앤다.
2. **제목은 판 안 왼쪽 위에 큰 글자**(h2, 24~30px, 굵게)로. 나무 간판 모양 제목판(`*-sign`)은 쓰지 않는다. 닫기(×)는 오른쪽 위 둥근 회색 단추(`.x-btn`, 이미 모던).
3. 안쪽 카드는 흰 판 위의 **연한 회색 면(`--bd-surface-2`) 또는 흰 카드 + 그림자**, 모서리 16~20, 테두리 없음. 줄 사이는 가는 선(`--bd-line`) 또는 간격.
4. 단추는 전역 규칙(`modern.css`)이 알약 모양으로 이미 바꿔 놓았다: 주 = 검정(`.btn.primary`), 보조 = 연회색, 위험 = 빨강. 창 안 작은 단추는 높이 36~44.
5. 칩·태그는 알약, 연한 색 면 + 진한 글자 (예: `--bd-awaiting-bg` + `--bd-awaiting-ink`). 대비 4.5:1 이상. 색만으로 뜻을 전하지 않는다.
6. 글자는 칸을 절대 넘지 않는다: 줄 수 제한(`line-clamp`), `min-width: 0`, `word-break: keep-all` + `overflow-wrap: anywhere`, 잘리면 `title`에 전체.
7. 창 크기·자리는 1536×1024 무대 안에서 넘치지 않게. 풀스크린 장면 창(회의실 `.mt`, 업무 일지 `.dy`, 완성작 `.tr`)은 배경 그림을 없애고 `--bd-bg` 바탕 + 흰 판으로.
8. 키보드 초점 링은 3px `--bd-accent-bright`, 오프셋 2. 움직임은 150ms, `html.calm`(효과 끔)이면 없다.
9. 기능·글·DOM 구조·`aria-*`·클래스 이름은 바꾸지 않는다. **CSS로 덮어쓰는 것이 원칙** (`popups.css`는 건드리지 않는다). DOM을 바꿔야만 하면 `popups.js`의 그 줄만 최소로 고치고 이유를 보고한다.

## 결재 취소 단추 (2026-10-06, CEO 요청: 결재 대기 카드를 치울 길이 없었다)

- **결재함은 몇 통이든 모두 닿는다**: 편지 칸(`.ib-tray`)만 스크롤(최대 높이 456, 4통 반쯤 보이면 더 있다는 뜻), 아래 줄(`.ib-foot`: [나중에 보기]·그룹 단추)은 늘 보인다. 확인 창을 다녀오거나 편지가 줄어도 스크롤 자리를 지킨다(`st.scroll`). "그 밖에 N통" 안내는 없앴다.
- **묶음 취소는 그룹별이다** (CEO 요청: Grok 보고서 9통만 지우려다 외부 AI의 기획안까지 지우는 실수를 막으려고): 지금 탭('결재함' 또는 '나중에 보기')의 결재 대기를 **프로젝트 + 종류 이름**으로 묶어(`waitingGroups`, 처음 나온 순서) 그룹마다 단추 하나. 종류 이름은 편지 칩(`tagOf`)과 같다(보고서·기획 회의·스킬 공부·MCP 만들기·새 직원…). 다만 개발 카드의 칩은 검사 결과('품질 합격'·'검사 없음')라서 종류 이름(개발·디자인·집필)으로 묶는다.
  - 그룹이 하나뿐이면 [모두 취소 (N)] 하나. 그룹이 여럿이면 [<프로젝트> <종류> 모두 취소 (N)]를 그룹마다 두고 **"전부 취소"는 두지 않는다**. 프로젝트가 하나뿐인 회사는 프로젝트 이름을 붙이지 않는다. 단추가 많으면 한 줄에 여러 개 + 줄바꿈(`.ib-groups`, 3줄 넘으면 이 영역만 스크롤)이라 결재함이 기준 판 밖으로 안 나간다.
  - 확인 창은 그 그룹만 센다: "<프로젝트> <종류> N건을 모두 취소할까요?" + 앞 5건(번호·제목, `외 M건`) + 되돌릴 수 없고 결과 파일은 지우지 않는다는 글. 서버로는 `POST /api/tasks/cancel-waiting` 한 번(ids = 그 그룹, 100건 넘으면 나눠서). 서버가 결재 대기가 아니게 된 것은 건너뛰고 이유를 알려 주면 알림에 첫 이유를 보인다.
- **묶음 취소는 PC 화면에만 있다.** 휴대폰(`/m`)은 상세 화면의 [취소](확인 창) 한 건씩만 — 결재 대기 상태에서도 보인다. `/m/api/cancel-waiting` 같은 길은 없다(404).
- 점검: `node tools/dev/cancel_waiting_browser.cjs [--shots]`(연습용 서버 셋 8811·8812·8813을 스스로 띄움 — 9통 모두 닿기, 한 통·그룹 취소와 '아니요', 한 그룹만 취소해도 다른 그룹은 그대로, 진짜 결재함 모양(Core Courier 보고서 9 + Studio Docs 기획 1), 종류별 창, 정지 중 잠금, 휴대폰, 창 크기 3가지 넘침 없음; `--shots`는 modern-inbox-cancel.png(그룹 하나)·modern-inbox-cancel-groups.png(그룹 둘)) · `python -m unittest tests.test_cancel_waiting`.

## 창 크기에 맞추기 (2026-10-06)

- 기준 무대는 1536×1024이지만, 창 비율이 달라도 **검은 띠 없이 창을 꽉 채운다**. `app.js` `fit()`이 가로·세로 중 빠듯한 쪽에 맞춘 확대 비율 `--s`를 정하고, `style.css`의 `#stage`는 실제 크기를 창 크기 ÷ `--s`(`--sw`·`--sh`)로 잡는다. 그래서 가로로 긴 창에서는 가로가, 세로로 긴 창에서는 세로가 1536/1024보다 커진다.
- 껍데기(`#layer-board::before` = `inset: 12px`)·위쪽 바(`left/right 12`)·왼쪽 메뉴(`left 28, top 100, bottom 28`)·가운데 구역(`.bd-main` = `left 252, top 100, right 28, bottom 120`)·명령창(`bottom 38`, 가운데 구역의 가운데)은 창과 함께 늘어난다. 새 페이지는 `.bd-main` 안에서 `flex`·`grid`·`fr`로 만들고 **고정 가로 크기를 쓰지 않는다**.
- 팝업은 기준 크기(1536×1024) 그대로 그려져 있어서 `#popup-host`를 그 크기의 판으로 두고 `--ox`·`--oy`(남는 길이의 절반)만큼 옮겨 **가운데에** 둔다. 오른쪽 위에 붙는 팝업(알림 `.al`)과 에너지 안내 말풍선(`.tip`)만 창 너비를 따라가게 따로 맞췄다.
